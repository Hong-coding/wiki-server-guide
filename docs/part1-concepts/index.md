# Part 1. 웹 서버 기초 개념

이 파트는 "서버를 띄운다"는 말이 실제로 무슨 뜻인지 **내 손으로 확인하며** 이해하는 곳입니다. 브라우저 주소창에 `http://localhost:5180`을 입력하고 Enter를 누른 순간부터 화면에 글자가 뜨기까지, 그 사이에 있는 부품을 하나씩 꺼내 봅니다.

<PartLessons dir="part1-concepts" />

## 이 파트가 왜 필요한가요?

Part 6에서 ts-wiki를 개발 서버 · Docker · GitHub Pages로 띄우다 보면 이런 문장들을 만납니다.

- `Port 5180 is in use, trying another one...`
- 내 PC에서는 열리는데 옆자리 PC에서는 안 열린다
- `npm ci`는 되는데 `npm install`은 결과가 다르다
- 개발 서버에서는 보이는데 빌드하면 링크가 깨진다

명령을 외워서는 이런 문제를 풀 수 없습니다. **HTTP, 포트, localhost와 0.0.0.0, 정적과 동적, npm, 빌드**가 각각 무엇인지 알아야 "어느 부품이 문제인지" 짐작할 수 있습니다. 이 파트는 그 부품 이름과 역할을 정확히 익히는 파트입니다.

## 학습 흐름

| 순서 | 레슨 | 무엇을 하나요 |
|---|---|---|
| 1 | 웹은 어떻게 동작하나 | 브라우저(클라이언트)와 서버가 HTTP 요청·응답을 주고받는 모습을 `curl -i`로 직접 봅니다. |
| 2 | 정적 사이트와 동적 서버 | 미리 만들어 둔 파일을 보내는 서버와, 요청마다 응답을 새로 만드는 서버를 직접 띄워 비교합니다. |
| 3 | localhost · 포트 · 호스트 · IP | `127.0.0.1`과 `0.0.0.0`의 차이, 포트 충돌, 방화벽을 실험하고 사용 중인 포트를 찾습니다. |
| 4 | Node.js와 npm | `package.json`, `node_modules`, `package-lock.json`, `npm ci`와 `npm install`, `npx`, 스크립트를 익힙니다. |
| 5 | 정적 사이트 생성기(SSG)와 빌드 | 빌드할 때 HTML을 미리 만들어 두는 원리를, 20줄짜리 생성기를 직접 만들어 봅니다. |

레슨 1~3은 "서버" 쪽, 레슨 4~5는 "빌드" 쪽입니다. [이 가이드에서 만들 것](../part0-start/01-what-we-build)의 그림으로 말하면 1~3은 **[4] 서버 ↔ [5] 브라우저**, 4~5는 **[1] 원고 → [2] 빌드 → [3] 결과물**을 다룹니다.

## 이 파트를 마치면

- 브라우저에 페이지가 뜨기까지의 과정을 "요청 → 응답 → 화면 그리기"로 설명할 수 있습니다.
- `curl -i`로 응답 상태 코드와 헤더를 읽을 수 있습니다.
- 정적 사이트와 동적 서버의 차이를 말하고, ts-wiki가 왜 정적 사이트인지 설명할 수 있습니다.
- `localhost`, `127.0.0.1`, `0.0.0.0`, 포트를 구분하고, 어떤 프로그램이 포트를 쓰는지 찾을 수 있습니다.
- `package.json`의 스크립트를 읽고, `npm ci`와 `npm install`을 상황에 맞게 고를 수 있습니다.
- "빌드한다"가 무엇을 만드는 일인지, 개발 서버와 무엇이 다른지 설명할 수 있습니다.

## 막힐 때

- **실습 서버를 켰는데 접속이 안 된다** → 서버를 켠 터미널의 로그에 찍힌 주소와 포트를 다시 읽습니다. 포트가 바뀌어 있는 경우가 많습니다.
- **`curl`을 쳤더니 이상한 표가 나온다** → Windows PowerShell 5.1에서는 `curl`이 다른 명령의 별명입니다. `curl.exe`로 입력합니다(레슨 1에서 설명).
- **용어가 섞인다** → 각 레슨의 "비유로 이해하기"로 돌아가 봅니다. 레슨 1의 "식당" 비유가 파트 전체에 이어집니다.
- **실습 후 서버가 남아 있는 것 같다** → 레슨 3의 "포트를 쓰는 프로그램 찾기"로 확인하고 끕니다.
