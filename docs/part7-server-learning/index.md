# Part 7. 서버 띄우기 학습 로드맵

Part 6까지 마쳤다면 ts-wiki를 개발 서버·Docker(nginx)·GitHub Pages 세 가지 방법으로 띄울 수 있습니다. 그런데 지금까지는 **남이 만든 서버**(VitePress 개발 서버, nginx, GitHub Pages)를 **설정만 해서** 썼습니다. 이 파트에서는 한 걸음 더 들어가, 서버를 **직접 만들고**, **앞단에 프록시를 세우고**, **리눅스에서 운영하는** 법을 어떤 순서로 공부하면 되는지 다룹니다.

## 왜 이 파트가 필요한가

- **위키는 시작일 뿐입니다.** 회사에서 마주칠 서버는 대부분 "정적 파일 몇 개"가 아니라, 요청마다 무언가를 계산해 돌려주는 프로그램입니다. 그래도 출발점은 같습니다. "요청을 받아 응답을 돌려주는 프로그램"이라는 뼈대입니다.
- **설정만 외우면 고장 났을 때 손을 못 댑니다.** ts-wiki의 `nginx.conf`에 있는 `try_files $uri $uri.html $uri/ =404;`가 무슨 일을 하는지, 같은 일을 하는 코드를 직접 짜 보면 한 번에 이해됩니다.
- **서버 공부는 범위가 넓어서 길을 잃기 쉽습니다.** 리눅스, 네트워크, 컨테이너, CI/CD, 보안… 무엇부터 할지 정해 두지 않으면 튜토리얼만 옮겨 다니다 지칩니다. 이 파트는 순서와 "여기까지 하면 통과" 기준을 정해 줍니다.

## 학습 흐름

```text
7-1 로드맵              ─ 8단계 학습 지도와 8주 계획 (전체 그림)
7-2 Node.js HTTP 서버    ─ 프레임워크 없이 정적 파일 서버를 직접 작성 (dist 서비스)
7-3 Express             ─ 같은 서버를 프레임워크로: 미들웨어·헬스 체크·에러 처리
7-4 리버스 프록시        ─ nginx가 앞에서 받아 Node로 넘기기, 가상 호스트, HTTPS 개념
7-5 리눅스 기초          ─ 컨테이너 안에서 파일·권한·프로세스·포트·로그 다루기
7-6 운영 기본기          ─ 로그·재시작·헬스 체크·백업·업데이트·보안 체크리스트
7-7 연습 과제·자가 진단   ─ 단계별 과제 12개와 25문항 체크리스트
```

7-2와 7-3은 같은 ts-wiki 빌드 결과물(`docs/.vitepress/dist`)을 서비스하는 서버를 두 번 만듭니다. 한 번은 맨손으로, 한 번은 프레임워크로 만들어 보면 "프레임워크가 무엇을 덜어 주는지"가 몸으로 느껴집니다. 7-4에서는 7-3의 서버 앞에 nginx를 세워 실제 운영 구조와 같은 모양을 만듭니다.

## 이 파트를 마치면 할 수 있는 것

1. 서버 공부를 8단계로 나누고, 지금 내가 어느 단계에 있는지 스스로 판단할 수 있습니다.
2. Node.js 기본 모듈만으로 정적 파일 서버를 만들고, 경로 탐색 공격(`../`)을 막을 수 있습니다.
3. Express로 정적 파일·헬스 체크·로깅·에러 처리를 갖춘 서버를 만들 수 있습니다.
4. nginx를 리버스 프록시로 세워 Node 서버 앞에 두고, `502 Bad Gateway`가 왜 나는지 설명할 수 있습니다.
5. 리눅스 서버에서 파일·권한·프로세스·포트·로그를 확인하는 기본 명령을 쓸 수 있습니다.
6. 서버를 운영할 때 챙길 로그·재시작·백업·보안 항목을 체크리스트로 점검할 수 있습니다.

## 준비물

- Part 0에서 설치한 **Node.js**(이 파트의 예제는 Node 24.13.1에서 확인)와 **Docker Desktop**(Docker 25.0.3에서 확인)
- ts-wiki를 한 번 빌드한 결과물. 원본을 건드리지 않도록 **복사본에서** 빌드합니다(방법은 7-2에서 안내합니다).
- 실습 포트는 **8192~8196**을 씁니다. ts-wiki가 쓰는 5180·8090과 겹치지 않게 하려는 것입니다.

## 막힐 때 팁

::: tip 서버가 안 뜨거나 접속이 안 될 때 순서대로 봅니다
1. **터미널에 에러가 찍혔나?** 서버 프로그램은 대부분 실패 이유를 터미널에 출력합니다. 맨 아래 줄부터 읽습니다.
2. **그 포트에서 정말 무언가 기다리고 있나?** Windows는 `netstat -ano | findstr :8192`, macOS/Linux는 `lsof -i :8192` 또는 `ss -tlnp`로 봅니다.
3. **주소·포트를 정확히 쳤나?** `http://localhost:8192`와 `http://localhost:8912`는 다른 곳입니다.
4. **curl로 상태 코드를 따로 확인합니다.** `curl -i http://localhost:8192/` — 브라우저는 캐시 때문에 예전 화면을 보여 줄 때가 있습니다.
5. 그래도 모르겠으면 [문제 해결: 서버가 안 뜰 때](../part6-serve/06-troubleshooting)의 순서를 따라갑니다.
:::

::: warning 실습이 끝나면 꼭 끕니다
이 파트에서는 서버와 컨테이너를 여러 번 띄웁니다. 실습을 마칠 때마다 `Ctrl+C`로 서버를 끄고, `docker ps -a`로 남은 컨테이너가 없는지 확인합니다. 켜 둔 채 잊어버리면 다음 실습에서 "포트가 이미 사용 중" 에러를 만나게 됩니다.
:::
