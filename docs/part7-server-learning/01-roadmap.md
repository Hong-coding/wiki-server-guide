# 서버 학습 로드맵

<LessonMeta level="실전" :minutes="30" prev="서버가 안 뜰 때 증상별로 원인을 좁혀 가는 순서를 익혔습니다." />

## 이번에 배울 것

- 서버를 띄우고 운영하는 공부를 **8단계**로 나누어 설명할 수 있다.
- 각 단계에서 무엇을 배우고, 어떤 실습을 하고, 어디까지 하면 "통과"인지 말할 수 있다.
- 지금까지 이 가이드에서 한 일이 8단계 중 어디에 해당하는지 짚을 수 있다.
- 8주짜리 학습 계획을 내 상황에 맞게 고쳐 쓸 수 있다.

## 먼저 알아 둘 것

- [Part 6. 서버 띄우기와 배포](../part6-serve/)를 한 번 끝까지 따라 해 보면 이 레슨의 1·4·5·6·7단계가 훨씬 잘 와닿습니다.
- [정적 사이트와 동적 서버](../part1-concepts/02-static-vs-dynamic)의 차이를 알고 있으면 좋습니다.

## 비유로 이해하기

서버 공부는 **가게를 차리는 일**과 닮았습니다. "한빛 카페"를 연다고 해 봅시다.

| 단계 | 카페에 비유하면 | 서버로 말하면 |
|---|---|---|
| 1 | 진열장에 만들어 둔 빵을 놓고 손님이 집어 가게 한다 | 미리 만든 HTML 파일을 그대로 내준다(정적 파일 서비스) |
| 2 | 직접 계산대에 서서 주문을 받고 빵을 건넨다 | 요청을 받아 응답을 돌려주는 프로그램을 직접 짠다 |
| 3 | 포스기·주문 앱 같은 도구를 들여온다 | 프레임워크(Express)로 반복되는 일을 맡긴다 |
| 4 | 직원이 쓰러져도 대신 설 사람을 정해 둔다 | 서버가 죽으면 자동으로 다시 켠다(프로세스 관리) |
| 5 | 건물 입구에 안내 데스크와 간판, 보안 출입문을 둔다 | 리버스 프록시·도메인·HTTPS |
| 6 | 어느 상가로 옮겨도 똑같이 차릴 수 있는 이동식 매장 | 컨테이너(Docker) |
| 7 | 새 메뉴가 나오면 정해진 절차대로 매장에 자동 반영 | CI/CD(자동 빌드·배포) |
| 8 | CCTV·장부·금고·문단속 | 모니터링·로그·백업·보안 |

중요한 점은 **순서**입니다. 계산대에 서 본 적 없는 사람이 프랜차이즈 본사 시스템(쿠버네티스 같은 대규모 운영 도구)부터 공부하면, 무엇을 왜 자동화하는지 몰라 금방 지칩니다. 아래 단계를 하나씩 "통과"하며 올라갑니다.

## 개념 설명

### 전체 지도

```text
 1 정적 파일 서비스      ← 이미 dist를 nginx·preview로 띄워 봄 (Part 6)
 2 직접 만든 HTTP 서버    ← 7-2
 3 프레임워크 서버        ← 7-3
 4 프로세스 관리·재시작   ← Part 6-4(Compose restart) + 7-6
 5 리버스 프록시·도메인·HTTPS ← Part 3-5(nginx) + 7-4
 6 컨테이너              ← Part 3-6 + Part 6-3·6-4
 7 CI/CD                ← Part 3-7 + Part 6-5
 8 모니터링·로그·백업·보안 ← 7-5 + 7-6
```

이 가이드를 Part 6까지 마쳤다면 1·6·7단계는 이미 한 번 경험했습니다. 다만 "남이 만든 설정을 따라 친 것"과 "빈 화면에서 스스로 구성할 수 있는 것"은 다릅니다. 각 단계의 **통과 기준**은 후자를 기준으로 적었습니다.

### 1단계. 정적 파일 서비스

- **배울 것**: 정적 파일(미리 만들어 둔 HTML·CSS·JS·이미지)이 무엇인지, 웹 서버가 "주소 → 파일"로 바꾸는 규칙, 상태 코드 200·404, `Content-Type` 헤더(브라우저에게 "이건 HTML이야", "이건 이미지야"라고 알려 주는 값).
- **실습 과제**: ts-wiki 복사본을 `npm run build`로 빌드하고, `npm run preview`와 Docker nginx 두 가지로 `dist`를 띄웁니다. `curl -i`로 응답 헤더를 확인합니다.
- **통과 기준**: "`/guide/roadmap` 주소를 요청하면 서버가 어느 파일을 찾아 돌려주는가"를 말로 설명할 수 있고, 없는 주소에서 404가 나오는 것을 curl로 보여 줄 수 있다.
- **관련 레슨**: [정적 사이트 생성기와 빌드](../part1-concepts/05-ssg), [빌드 결과물을 서버로 서비스하기](../part6-serve/02-static-serve), [nginx: 정적 파일 웹 서버](../part3-libraries/05-nginx)

### 2단계. 직접 만든 HTTP 서버

- **배울 것**: HTTP 요청의 구성(메서드·경로·헤더), 응답의 구성(상태 코드·헤더·본문), 포트에서 "기다린다(listen)"는 뜻, 파일 경로를 다룰 때의 보안 문제(경로 탐색 공격).
- **실습 과제**: Node.js 기본 모듈(`node:http`, `node:fs/promises`, `node:path`)만으로 `dist`를 서비스하는 서버를 TypeScript로 작성합니다.
- **통과 기준**: 프레임워크 없이 200·404·405를 구분해 돌려주는 서버를 직접 짤 수 있고, `..%2f`가 들어간 요청이 왜 위험한지 실제로 보여 줄 수 있다.
- **관련 레슨**: [Node.js로 정적 파일 서버 직접 만들기](./02-node-http)

### 3단계. 프레임워크 서버 (Express)

- **배울 것**: 미들웨어(요청이 응답에 닿기 전에 차례로 거치는 함수들), 라우팅(주소별로 처리 함수를 나누는 것), 헬스 체크, 에러 처리, 환경 변수로 설정 받기.
- **실습 과제**: 2단계 서버를 Express 5로 다시 만들고 `/health`, 요청 로그, 에러 처리기를 붙입니다.
- **통과 기준**: 2단계 코드와 비교해 "프레임워크가 덜어 준 일" 3가지 이상을 말할 수 있고, `PORT` 환경 변수만 바꿔 다른 포트로 띄울 수 있다.
- **관련 레슨**: [Express로 웹 서버 만들기](./03-express)

### 4단계. 프로세스 관리·재시작

- **배울 것**: 프로세스(실행 중인 프로그램 하나), 포그라운드·백그라운드, 터미널을 닫으면 왜 서버가 꺼지는지, 재시작 정책(죽으면 다시 켜기), pm2·systemd·Docker의 `restart` 옵션.
- **실습 과제**: 일부러 죽는 프로그램을 Docker `--restart on-failure:3`으로 띄워 재시작 횟수를 확인합니다. ts-wiki `docker-compose.yml`의 `restart: unless-stopped`를 다른 값으로 바꿔 차이를 봅니다(복사본에서).
- **통과 기준**: "PC를 재부팅해도 서버가 다시 떠 있게 하려면 무엇이 필요한가"를 두 가지 이상 방법으로 설명할 수 있다.
- **관련 레슨**: [서버에 상시 띄우기: Docker Compose](../part6-serve/04-compose), [운영 기본기](./06-ops)

### 5단계. 리버스 프록시·도메인·HTTPS

- **배울 것**: 리버스 프록시(손님 요청을 앞에서 받아 뒤의 서버에게 넘겨주는 서버), 가상 호스트(한 서버에서 이름별로 다른 사이트를 응답), DNS와 도메인, HTTPS·TLS·인증서, Let's Encrypt.
- **실습 과제**: Docker nginx를 앞에 세우고, PC에서 돌고 있는 Express 서버로 `proxy_pass`합니다. 뒤 서버를 끄고 `502 Bad Gateway`를 직접 만나 봅니다.
- **통과 기준**: "브라우저 → nginx → Node" 사이에 무슨 일이 일어나는지 그림으로 그릴 수 있고, 502와 504의 차이를 설명할 수 있다.
- **관련 레슨**: [리버스 프록시와 HTTPS 개념](./04-reverse-proxy), [nginx: 정적 파일 웹 서버](../part3-libraries/05-nginx)

### 6단계. 컨테이너

- **배울 것**: 이미지와 컨테이너, Dockerfile, 멀티 스테이지 빌드(빌드용 단계와 서비스용 단계를 나누는 것), 볼륨, 포트 연결(`-p 8090:80`), Compose.
- **실습 과제**: 3단계의 Express 서버를 `node:22-alpine` 기반 이미지로 만들고 Compose로 띄웁니다. 이미지 크기를 확인합니다.
- **통과 기준**: ts-wiki `Dockerfile`의 각 줄이 무엇을 하는지 설명할 수 있고, 내 서버용 Dockerfile을 빈 화면에서 쓸 수 있다.
- **관련 레슨**: [Docker와 Docker Compose](../part3-libraries/06-docker), [Docker 이미지로 묶기](../part6-serve/03-docker-nginx)

### 7단계. CI/CD

- **배울 것**: CI(지속적 통합: 올릴 때마다 자동으로 빌드·검사), CD(지속적 배포: 통과하면 자동으로 배포), GitHub Actions 워크플로 파일, 시크릿 관리.
- **실습 과제**: 내 저장소에 "push하면 `npm ci` → `npm run build`가 도는" 워크플로를 만들고, 일부러 빌드를 깨뜨려 실패 표시를 확인합니다.
- **통과 기준**: ts-wiki `deploy.yml`의 `build`·`deploy` 두 작업이 무엇을 하는지 설명할 수 있고, 내 프로젝트에 맞게 고칠 수 있다.
- **관련 레슨**: [GitHub Actions와 Pages 배포 액션](../part3-libraries/07-github-actions), [GitHub Pages 자동 배포](../part6-serve/05-github-pages)

### 8단계. 모니터링·로그·백업·보안

- **배울 것**: 로그 읽기(`tail -f`, `docker logs`), 헬스 체크 자동 확인, 디스크·메모리 확인, 백업과 복구 연습, 보안 기본(열린 포트 최소화, 시크릿 관리, 최소 권한, 의존성 점검).
- **실습 과제**: 리눅스 컨테이너 안에서 nginx를 띄우고 프로세스·포트·로그를 명령으로 확인합니다. `npm audit`으로 ts-wiki 복사본의 의존성을 점검합니다.
- **통과 기준**: "서버가 느리다/죽었다"는 연락을 받았을 때 확인할 순서를 5단계 이상 말할 수 있고, 7-6의 보안 체크리스트를 내 서버에 적용해 볼 수 있다.
- **관련 레슨**: [서버 운영에 필요한 리눅스 기초](./05-linux-basics), [운영 기본기](./06-ops), [문제 해결](../part6-serve/06-troubleshooting)

### 단계별 공부 요령

- **한 단계에 하나의 서버만** 다룹니다. 2단계에서 데이터베이스까지 붙이려 하면 원인을 찾을 수 없는 문제가 동시에 여러 개 생깁니다.
- **일부러 망가뜨립니다.** 포트를 겹치게 띄우기, 뒤 서버 끄기, 설정 파일에 오타 넣기. 에러 메시지를 미리 만나 두면 실전에서 당황하지 않습니다.
- **통과 기준을 남에게 설명하듯 말해 봅니다.** 설명이 막히는 곳이 아직 모르는 곳입니다. 7-7의 자가 진단표를 단계마다 다시 봅니다.
- **메모를 남깁니다.** 실행한 명령과 실제 출력을 그대로 적어 두면, 나만의 "명령어 모음"이 됩니다. [명령어 모음](../appendix/01-commands)을 출발점으로 써도 됩니다.

### 8주 학습 계획 예시

하루 1시간, 주 5일을 기준으로 잡았습니다. 이미 아는 단계는 건너뛰고, 막히는 단계는 한 주 더 써도 됩니다.

| 주차 | 단계 | 할 일 | 주말 점검 |
|---|---|---|---|
| 1주 | 1 | Part 1 개념 복습, ts-wiki 복사본 빌드, preview·nginx로 dist 서비스, `curl -i`로 헤더 읽기 | 200·404·`Content-Type`을 설명할 수 있나 |
| 2주 | 2 | 7-2 따라 하기, MIME 표 늘리기, 경로 탐색 공격 재현과 방어 | 프레임워크 없이 서버를 다시 짤 수 있나 |
| 3주 | 3 | 7-3 따라 하기, `/health`·로그·에러 처리, 7-7 과제 ⭐ 3개 | 2단계와 3단계 코드를 비교해 설명할 수 있나 |
| 4주 | 4·6 | Express 서버를 Dockerfile·Compose로 묶기, 재시작 정책 실험 | 재부팅 후에도 서버가 떠 있나 |
| 5주 | 5 | 7-4 따라 하기, 가상 호스트 2개, 502 재현, HTTPS 절차 정리 | 요청 흐름을 그림으로 그릴 수 있나 |
| 6주 | 8(리눅스) | 7-5 따라 하기, 컨테이너 안에서 파일·권한·프로세스·포트 다루기 | 명령만으로 "무엇이 포트를 잡고 있나" 찾을 수 있나 |
| 7주 | 7 | 내 저장소에 빌드 워크플로 만들기, 일부러 실패시키기 | push → 자동 빌드가 도나 |
| 8주 | 8(운영) | 7-6 체크리스트 적용, 7-7 과제 ⭐⭐⭐ 1개 이상, 자가 진단 | 자가 진단 점수가 기준을 넘나 |

::: tip 회사 일과 병행할 때
주 3일밖에 못 한다면 주차를 그대로 두고 "할 일"만 절반으로 줄이는 것보다, **기간을 12주로 늘리는 편**이 낫습니다. 단계를 건너뛰면 다음 단계에서 같은 시간을 다시 쓰게 됩니다.
:::

### 이 로드맵에 없는 것

데이터베이스, 로그인(인증), 로드밸런싱(여러 대에 요청 나누기), 쿠버네티스(컨테이너 여러 개를 여러 서버에 배치·관리하는 도구), 클라우드 서비스(AWS 등)는 일부러 뺐습니다. 8단계를 모두 통과한 뒤에 하나씩 골라 같은 방식(배울 것 → 실습 → 통과 기준)으로 계획을 세우면 됩니다. 참고할 만한 자료는 [참고 자료](../appendix/04-resources)에 모아 두었습니다.

## ts-wiki에서는

ts-wiki는 작은 프로젝트지만 8단계 중 여러 단계가 실제 파일로 들어 있습니다. 로드맵을 공부할 때 "이 단계의 예시가 ts-wiki 어디에 있나"를 찾아보면 개념이 구체적으로 잡힙니다.

| 단계 | ts-wiki 파일 | 해당 부분 |
|---|---|---|
| 1 정적 파일 | `package.json` | 9번 줄 `"build": "vitepress build docs"` — 결과물이 `docs/.vitepress/dist`에 생깁니다. |
| 1 정적 파일 | `nginx.conf` | 4번 줄 `root /usr/share/nginx/html;`, 9번 줄 `try_files $uri $uri.html $uri/ =404;` |
| 4 재시작 | `docker-compose.yml` | 7번 줄 `restart: unless-stopped` |
| 5 프록시·호스트 | `nginx.conf` | 2~3번 줄 `listen 80;`, `server_name _;` — 이름을 가리지 않는 기본 서버 |
| 6 컨테이너 | `Dockerfile` | 2번 줄 `FROM node:22-alpine AS build`, 11번 줄 `FROM nginx:1.27-alpine` — 멀티 스테이지 빌드 |
| 6 컨테이너 | `docker-compose.yml` | 5~6번 줄 `ports:` / `- "8090:80"` |
| 7 CI/CD | `.github/workflows/deploy.yml` | 4~7번 줄 `on: push: branches: [main]`, 29~30번 줄 `npm ci` · `npm run build` |
| 8 보안 | `.gitignore` | 7~8번 줄 `.env`, `.env.*` — 시크릿 파일이 저장소에 올라가지 않게 막습니다. |

반대로 ts-wiki에 **없는** 것도 보입니다. 2·3단계(직접 만든 서버)는 없습니다. nginx와 VitePress가 대신해 주기 때문입니다. 그래서 7-2·7-3에서 그 빈칸을 직접 채워 봅니다.

## 자주 하는 실수

1. **증상**: 튜토리얼을 여러 개 따라 했는데 빈 화면에서는 아무것도 못 만든다.
   **원인**: 따라 치기만 하고 "통과 기준"을 스스로 확인하지 않았습니다.
   **해결**: 각 단계가 끝나면 문서를 덮고 처음부터 다시 만들어 봅니다. 막힌 곳만 다시 봅니다.
2. **증상**: 2단계를 하다가 데이터베이스·로그인까지 붙였더니 어디서 에러가 나는지 모르겠다.
   **원인**: 한 번에 여러 단계를 섞었습니다.
   **해결**: 한 단계에 하나의 서버만 다룹니다. 확장은 8단계를 통과한 뒤에 합니다.
3. **증상**: 실습할 때마다 `EADDRINUSE`(포트가 이미 사용 중) 에러가 난다.
   **원인**: 지난번에 띄운 서버나 컨테이너를 끄지 않았습니다.
   **해결**: 실습 끝에 `Ctrl+C`, `docker ps -a` 확인을 습관으로 만듭니다. 포트를 잡은 프로그램을 찾는 법은 [리눅스 기초](./05-linux-basics)와 [문제 해결](../part6-serve/06-troubleshooting)에 있습니다.
4. **증상**: ts-wiki 원본이 실습 중에 망가졌다.
   **원인**: 원본 폴더에서 실습했습니다.
   **해결**: 항상 복사본(예: `D:\lab\ts-wiki-copy`)에서 실습합니다. 원본은 `git status`로 깨끗한지 확인합니다.

## 직접 해 보기

### 과제 1 ⭐ 내 위치 찾기

8단계 각각에 대해 "해 봤다 / 따라만 해 봤다 / 처음 듣는다" 중 하나로 표시해 봅니다.

::: details 힌트
Part 6까지 마쳤다면 보통 1·6·7단계가 "따라만 해 봤다", 2·3·5단계가 "처음 듣는다"입니다. "따라만 해 봤다"인 단계는 통과 기준을 다시 확인하고, 통과하지 못하면 그 단계부터 시작합니다.
:::

### 과제 2 ⭐ ts-wiki 파일과 단계 연결하기

ts-wiki의 `Dockerfile`, `nginx.conf`, `docker-compose.yml`, `.github/workflows/deploy.yml`, `.gitignore`를 열어 각 파일이 몇 단계에 해당하는지 적어 봅니다.

::: details 정답 보기
`Dockerfile` 6단계, `nginx.conf` 1·5단계, `docker-compose.yml` 4·6단계, `deploy.yml` 7단계, `.gitignore` 8단계(시크릿 보호). 위의 "ts-wiki에서는" 표와 비교해 봅니다.
:::

### 과제 3 ⭐⭐ 내 8주 계획 세우기

위 8주 계획 표를 복사해, 내가 실제로 쓸 수 있는 시간에 맞게 주차와 할 일을 고쳐 봅니다. 각 주에 "주말 점검" 질문을 하나씩 직접 써 넣습니다.

::: details 힌트
주말 점검 질문은 "~를 설명할 수 있나", "~가 되나"처럼 **예/아니요로 답할 수 있게** 씁니다. "열심히 했나"는 점검이 되지 않습니다.
:::

### 과제 4 ⭐⭐⭐ 9단계 설계하기

로드맵에 없는 주제(예: 데이터베이스) 하나를 골라 "배울 것 / 실습 과제 / 통과 기준 / 참고 자료" 4칸을 직접 채워 봅니다.

::: details 예시
- **주제**: 데이터베이스(PostgreSQL)
- **배울 것**: 테이블·행·열, SQL `SELECT`/`INSERT`, 접속 문자열, 접속 정보를 환경 변수로 받기
- **실습 과제**: Docker로 PostgreSQL 컨테이너를 띄우고, Express에 `/notes` API를 만들어 메모를 저장·조회
- **통과 기준**: 서버를 재시작해도 메모가 남아 있고, 접속 비밀번호가 코드에 없다
- **참고 자료**: PostgreSQL 공식 문서, Docker Hub의 postgres 이미지 설명
:::

## 확인 퀴즈

1. 1단계(정적 파일 서비스)와 2단계(직접 만든 HTTP 서버)의 가장 큰 차이는 무엇입니까?
2. "통과 기준"이 "따라 해 봤다"가 아니라 "빈 화면에서 할 수 있다"로 적힌 이유는 무엇입니까?
3. ts-wiki의 `restart: unless-stopped`는 8단계 중 몇 단계에 해당합니까?
4. 2단계를 공부하면서 데이터베이스까지 함께 붙이면 왜 좋지 않습니까?

::: details 정답 보기
1. 1단계는 이미 만들어진 서버(nginx 등)에 설정만 해서 파일을 내주고, 2단계는 요청을 받아 응답을 돌려주는 프로그램 자체를 직접 작성합니다.
2. 따라 치기만 하면 각 줄의 이유를 모른 채 넘어가기 쉽고, 실제 업무에서는 따라 할 문서가 없는 상황이 더 많기 때문입니다.
3. 4단계(프로세스 관리·재시작)입니다.
4. 문제가 생겼을 때 원인이 서버 코드인지, DB인지, 둘의 연결인지 구분하기 어려워지기 때문입니다. 한 번에 하나만 늘립니다.
:::

## 정리

- 서버 공부는 정적 파일 → 직접 만든 서버 → 프레임워크 → 프로세스 관리 → 리버스 프록시·HTTPS → 컨테이너 → CI/CD → 운영(모니터링·로그·백업·보안) 순서로 올라갑니다.
- 각 단계는 "배울 것 · 실습 과제 · 통과 기준"으로 점검하고, 통과 기준은 **빈 화면에서 스스로 할 수 있는가**입니다.
- ts-wiki에는 1·4·5·6·7·8단계의 예가 실제 파일로 들어 있고, 2·3단계는 이 파트에서 직접 채웁니다.
- 한 단계에 하나만 다루고, 일부러 망가뜨려 에러를 미리 만나 둡니다.
- 8주 계획은 예시입니다. 시간을 줄이기보다 기간을 늘리는 편이 낫습니다.
