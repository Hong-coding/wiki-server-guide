# Part 6. 서버 띄우기와 배포

지금까지는 ts-wiki가 **무엇으로** 만들어졌는지 읽고, 비슷한 위키를 직접 만들어 봤습니다. 이 파트는 그 위키를 **실제로 띄워서 다른 사람이 볼 수 있게 하는 법**을 다룹니다. 같은 ts-wiki를 세 가지 방법으로 띄우고, 안 뜰 때 원인을 찾는 연습까지 합니다.

## 왜 이 파트가 필요한가

위키는 "만들었다"로 끝나지 않습니다. 누군가 브라우저 주소창에 주소를 넣었을 때 페이지가 떠야 쓸모가 있습니다. 그런데 "띄운다"에는 목적이 다른 여러 방법이 있습니다.

| 방법 | 언제 쓰나 | 누가 보나 | 이 파트의 레슨 |
|---|---|---|---|
| 개발 서버 (`npm run dev`) | 글을 쓰고 고치는 동안 | 나, 같은 네트워크의 동료 | 6-1 |
| 빌드 + 정적 서버 | 배포 직전에 결과물을 확인할 때 | 나 | 6-2 |
| Docker(nginx) | 사내 서버 PC에 계속 켜 둘 때 | 사내 사람들 | 6-3, 6-4 |
| GitHub Pages | 인터넷에 공개할 때 | 누구나 | 6-5 |

방법마다 "언제 꺼지는가", "글을 고치면 언제 반영되는가", "어떤 주소로 들어가는가"가 다릅니다. 이 차이를 모르면 "어제는 됐는데 오늘은 안 돼요" 같은 문제가 생겼을 때 어디부터 봐야 할지 모릅니다.

## 학습 흐름

```text
6-1 개발 서버          → 서버 프로그램이 포트를 열고 기다린다는 감각
      │
6-2 빌드 결과물 서비스 → "빌드 = HTML 파일 묶음", 아무 정적 서버로 띄울 수 있다
      │
6-3 Docker 이미지      → 빌드 + nginx를 한 상자에 담는다
      │
6-4 Docker Compose     → 그 상자를 명령 한 줄로 켜고, 재부팅 후에도 다시 켜지게 한다
      │
6-5 GitHub Pages       → push 한 번으로 인터넷에 공개한다
      │
6-6 문제 해결          → 증상 → 원인 → 확인 명령 → 해결
```

앞 레슨의 결과물을 뒤 레슨이 그대로 씁니다. 6-2에서 만든 `dist` 폴더를 6-3에서 nginx가 서비스하고, 6-3의 Dockerfile을 6-4의 Compose가 부릅니다. 순서대로 따라오기를 권합니다.

## 실습 방식

이 파트의 명령은 작성 시점(2026-10)에 아래 환경에서 **실제로 실행해서** 나온 출력을 옮겼습니다.

- Windows 11, Node.js 24.13.1, npm 11.8.0, Docker 25.0.3(Docker Compose v2.24.5)
- ts-wiki: VitePress 1.6.3(그 밑의 Vite 5.4.21), Vue 3.5.13

출력에 나오는 이 PC의 IP 주소는 `<이 PC의 IP>`로 바꿔 적었습니다.

::: warning 원본 대신 복사본으로 실습하세요
실습 중에 일부러 설정을 망가뜨리는 단계가 있습니다. `D:\workspace\ts-wiki`를 직접 고치지 말고, `node_modules`·`dist`·`.git`을 뺀 복사본을 만들어 그 안에서 따라 하면 원본을 지킬 수 있습니다. 복사 방법은 [6-1](./01-dev-server)에 있습니다.
:::

::: tip 포트 번호
ts-wiki의 기본 포트(개발 서버 5180, Docker 8090)는 이미 켜 둔 위키와 겹칠 수 있으므로, 실습에서는 5190~5199, 8190~8199 같은 다른 번호를 씁니다. 왜 겹치면 안 되는지는 6-1에서 직접 겪어 봅니다.
:::

## 이 파트를 마치면

- `npm run dev`가 무엇을 하는지 설명하고, 포트와 접속 범위(`--host`)를 바꿔 띄울 수 있습니다.
- 빌드 결과물(`dist`)을 vitepress preview, `npx serve`, `npx http-server`, Python 같은 아무 정적 서버로 띄우고, 확장자 없는 주소에서 생기는 404를 고칠 수 있습니다.
- ts-wiki의 Dockerfile·nginx.conf·docker-compose.yml을 한 줄씩 설명하고, 이미지를 빌드해 컨테이너로 띄우고 정리할 수 있습니다.
- GitHub Actions로 Pages에 자동 배포되는 흐름을 설명하고, `gh run list`로 배포 기록을 볼 수 있습니다.
- 서버가 안 뜰 때 증상을 보고 원인 후보를 좁힌 뒤, 확인 명령으로 원인을 특정할 수 있습니다.

## 막힐 때 팁

1. **에러 메시지를 끝까지 읽습니다.** 맨 아래 줄이나 `error`, `Error`, `emerg`가 들어간 줄에 원인이 거의 다 적혀 있습니다.
2. **"서버가 떠 있는가"부터 확인합니다.** 포트를 누가 쓰고 있는지 보는 명령(Windows `netstat -ano | findstr :5190`, macOS/Linux `lsof -i :5190`)을 손에 익혀 두면 절반은 해결됩니다.
3. **브라우저 말고 `curl`로 확인합니다.** 브라우저는 캐시(cache, 한 번 받은 파일을 저장해 두고 다시 쓰는 것)를 쓰기 때문에 고친 내용이 안 보일 때가 있습니다. `curl -I 주소`는 서버가 지금 돌려주는 응답을 그대로 보여 줍니다.
4. **한 번에 하나만 바꿉니다.** 포트와 설정과 파일을 한꺼번에 바꾸면 무엇 때문에 고쳐졌는지(또는 망가졌는지) 알 수 없습니다.
5. 그래도 안 되면 [6-6 문제 해결](./06-troubleshooting)의 증상 표에서 비슷한 증상을 찾습니다.
