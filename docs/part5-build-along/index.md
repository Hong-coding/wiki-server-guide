# Part 5. 처음부터 따라 만들기

<PartLessons dir="part5-build-along" />

## 이 파트가 왜 필요한가

Part 4까지는 이미 완성된 ts-wiki를 **읽었습니다**. 남이 지은 집을 둘러보며 "이 기둥은 왜 여기 있지?"를 따져 본 셈입니다. 그런데 읽기만 해서는 빈 땅 앞에 섰을 때 어디서부터 시작해야 할지 막막합니다.

이 파트에서는 **빈 폴더 `my-wiki` 하나에서 시작해** 레슨 6개를 차례로 따라 하며 ts-wiki와 같은 구조의 작은 위키를 직접 만듭니다. 파일을 한 개씩 늘려 가면서 단계마다 브라우저에서 결과를 확인하므로, 어느 파일이 무엇을 바꾸는지 손으로 익힐 수 있습니다.

모든 명령과 출력은 작성 시점(2026-10)에 Windows 11 · Node 24.13.1 · npm 11.8.0 환경에서 **처음부터 실제로 따라 해 보고** 옮긴 것입니다.

## 학습 흐름

| 레슨 | 하는 일 | 끝나면 생기는 파일 |
|---|---|---|
| 5-1 | 빈 폴더 → npm 프로젝트 → VitePress 설치 → 첫 페이지 → 개발 서버 | `package.json`, `docs/index.md` |
| 5-2 | 레슨 페이지·홈 화면·정적 파일 추가, 링크와 dead link 체험 | `docs/part1-basics/*.md`, `docs/public/logo.svg` |
| 5-3 | 설정 파일로 상단 메뉴·사이드바·검색·한국어 문구 | `docs/.vitepress/config.mts` |
| 5-4 | 커리큘럼 파일 하나로 사이드바를 자동으로 만들기 | `docs/.vitepress/curriculum.mts`, 파트 소개 페이지 |
| 5-5 | 테마 확장, Vue 컴포넌트 3개, 브랜드 색 바꾸기 | `docs/.vitepress/theme/` 전체 |
| 5-6 | 빌드 → 결과물 살펴보기 → 미리보기 → 하위 경로 배포 체험 | `docs/.vitepress/dist/`(빌드 결과물) |

완성되면 폴더는 이렇게 됩니다(`node_modules`와 빌드 결과물은 뺐습니다).

```text
my-wiki/
├─ .gitignore
├─ package.json
├─ package-lock.json
└─ docs/
   ├─ index.md                     ← 홈 화면
   ├─ guide/checklist.md           ← 진도 체크리스트 페이지
   ├─ part1-basics/                ← 파트 1 (소개 + 레슨 3개)
   ├─ part2-deploy/                ← 파트 2 (소개 + 레슨 1개)
   ├─ public/logo.svg              ← 그대로 복사되는 정적 파일
   └─ .vitepress/
      ├─ config.mts                ← 사이트 설정
      ├─ curriculum.mts            ← 레슨 목록 단일 정의
      └─ theme/
         ├─ index.ts               ← 기본 테마 확장
         ├─ custom.css             ← 색·글꼴 덮어쓰기
         └─ components/            ← LessonMeta · PartLessons · ProgressChecklist
```

ts-wiki의 `docs/.vitepress/` 구조와 파일 이름까지 같게 맞췄습니다. 이 파트를 마친 뒤 ts-wiki 폴더를 열어 보면 "내가 만든 것과 같은 자리에 같은 파일이 있구나"가 보일 것입니다.

## 마친 뒤 할 수 있는 것

- 빈 폴더에서 VitePress 위키를 처음부터 만들고 개발 서버로 띄울 수 있습니다.
- `config.mts`에서 메뉴·사이드바·검색·다크 모드 문구를 고칠 수 있습니다.
- 레슨 목록을 한 파일(`curriculum.mts`)에 모아 두고, 레슨 추가를 한 줄 수정으로 끝낼 수 있습니다.
- Vue 컴포넌트를 만들어 마크다운 안에서 쓰고, 브라우저에만 있는 기능(localStorage)을 빌드 오류 없이 다룰 수 있습니다.
- 빌드 결과물을 미리보기로 확인하고, 하위 경로(`/my-wiki/`) 배포에 맞춰 `base`를 바꿀 수 있습니다.

여기서 만든 `my-wiki`는 [Part 6. 서버 띄우기와 배포](../part6-serve/)에서 Docker와 GitHub Pages로 띄우는 실습 재료로 그대로 쓸 수 있습니다.

## 준비물

- Node.js 20 이상(작성 시점 확인 환경은 24.13.1)과 npm. 확인: `node -v`, `npm -v`
- 코드 편집기(VS Code 권장)와 터미널. 설치가 안 되어 있다면 [준비물 설치](../part0-start/03-setup)를 먼저 봅니다.
- 인터넷 연결(처음 `npm install` 때 패키지를 내려받습니다).

## 막힐 때 팁

::: tip 막히면 이 순서로 확인합니다
1. **지금 어느 폴더에 있는지** 봅니다. 대부분의 명령은 `my-wiki` 폴더(= `package.json`이 있는 곳)에서 실행해야 합니다.
2. **터미널 출력의 첫 오류 줄**을 읽습니다. 아래로 길게 이어지는 `at ...` 줄은 대개 라이브러리 내부 위치라 처음에는 건너뛰어도 됩니다.
3. 레슨마다 있는 **"이 단계까지의 전체 파일 상태"** 와 내 파일을 한 줄씩 비교합니다. 쉼표 하나, 따옴표 하나 차이가 가장 흔한 원인입니다.
4. 설정 파일(`config.mts`)을 **처음 만들었을 때**는 개발 서버를 껐다 켭니다(이유는 5-3에서 봅니다).
5. 그래도 안 되면 `docs/.vitepress/cache` 폴더를 지우고 다시 `npm run dev`를 실행합니다. 지워도 다시 만들어지는 임시 폴더입니다.
:::

- 실습용 포트는 **5190**(개발 서버)과 **5191**(미리보기)을 씁니다. ts-wiki(5180)나 이 가이드(5181)를 함께 띄워 두어도 겹치지 않게 하려는 것입니다.
- 서버를 띄운 터미널은 그 서버 전용이 됩니다. 다른 명령은 **새 터미널 창**을 열어 실행하고, 다 쓰면 서버 터미널에서 `Ctrl+C`로 끕니다.
- 실습하다 꼬였다면 `my-wiki` 폴더를 통째로 지우고 5-1부터 다시 해도 30분이면 돌아옵니다. 처음부터 다시 해 보는 것 자체가 좋은 복습입니다.
