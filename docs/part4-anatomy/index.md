# Part 4. ts-wiki 해부하기

지금까지는 위키 서버를 이루는 개념(Part 1), 도구를 고른 이유(Part 2), 각 라이브러리의 사용법(Part 3)을 따로따로 배웠습니다. 이 파트에서는 그 조각들이 **실제 프로젝트 한 개 안에서 어떻게 맞물려 있는지**를 봅니다. 교재는 `D:\workspace\ts-wiki`이고, 파일을 하나씩 열어 **한 줄씩** 읽습니다.

<PartLessons dir="part4-anatomy" />

## 이 파트가 왜 필요한가요?

남이 만든 프로젝트를 처음 열면 대부분 이런 상태가 됩니다.

- 파일이 수십 개 보이는데 어디서부터 읽어야 할지 모릅니다.
- 설정 파일의 옵션 하나하나가 "지워도 되는 것"인지 "지우면 사이트가 망가지는 것"인지 구분이 안 됩니다.
- 같은 정보(예: 레슨 목록)가 여러 곳에 나오는 것 같은데, 고칠 때 어디를 고쳐야 하는지 모릅니다.

이 상태에서 Part 5(처음부터 따라 만들기)로 바로 가면, 따라 치기는 할 수 있어도 **왜 그렇게 치는지**는 모르는 채로 끝납니다. 그러면 내 위키에 맞게 조금만 바꾸려 해도 막힙니다. 그래서 따라 만들기 전에 완성품을 먼저 분해해 봅니다. 자동차 정비를 배울 때 새 차를 조립하기 전에 완성된 엔진을 먼저 뜯어 보는 것과 같습니다.

## 학습 흐름

```text
4-1 폴더 구조         ─ 어떤 파일이 어디 있고, 무엇이 git에 들어가나
 │
4-2 package.json     ─ 프로젝트의 신분증: 이름 · 스크립트 · 의존성
 │
4-3 config.mts       ─ 사이트 전체 설정 83줄을 한 줄씩
 │
4-4 curriculum.mts   ─ 레슨 목록을 한 곳에서만 관리하는 설계
 │
4-5 테마와 컴포넌트    ─ 기본 테마를 확장하고 Vue 컴포넌트 4개를 붙이는 법
 │
4-6 보조 스크립트·규칙 ─ 빌드가 깨지지 않게 하는 장치들
```

앞 레슨이 뒤 레슨의 바탕이 됩니다. 4-3에서 읽는 사이드바 생성 코드는 4-4의 `curriculum.mts`를 읽고 있고, 4-5의 컴포넌트도 같은 파일을 읽습니다. 순서대로 읽는 것을 권합니다.

## 이 파트를 마치면 할 수 있는 것

- ts-wiki의 파일 목록을 보고 각 파일이 무슨 일을 하는지, 지우면 무엇이 망가지는지 설명할 수 있습니다.
- `npm run dev`를 쳤을 때 `package.json`의 어느 줄이 실행되는지 따라갈 수 있습니다.
- `config.mts`의 옵션을 바꿨을 때 빌드 결과(HTML)가 어떻게 달라지는지 예측하고, 실제로 확인할 수 있습니다.
- 새 레슨 하나를 추가할 때 고쳐야 하는 파일이 어디인지 정확히 압니다.
- VitePress 기본 테마에 내 컴포넌트를 붙이는 방법과, 그때 지켜야 할 규칙(SSR, `withBase`)을 설명할 수 있습니다.
- 마크다운을 쓰다 빌드가 깨졌을 때 에러 메시지를 보고 원인을 짐작할 수 있습니다.

## 실습 준비: 원본 대신 복사본으로

이 파트의 실습은 **ts-wiki 원본을 고치지 않고 복사본에서** 합니다. 원본이 망가지면 다른 레슨을 따라 할 수 없기 때문입니다.

Windows(PowerShell):

```powershell
# 실습용 폴더로 이동한 뒤 실행합니다.
robocopy D:\workspace\ts-wiki .\ts-wiki-lab /E /XD node_modules dist cache .git
cd .\ts-wiki-lab
npm install
```

macOS/Linux(bash):

```bash
rsync -a --exclude node_modules --exclude dist --exclude cache --exclude .git <ts-wiki 경로>/ ./ts-wiki-lab/
cd ts-wiki-lab
npm install
```

- `robocopy`는 Windows에 들어 있는 복사 명령입니다. `/E`는 하위 폴더까지, `/XD`는 "이 이름의 폴더는 빼고"라는 뜻입니다. 복사가 끝나면 종료 코드 1을 돌려주는데, robocopy에서 1은 "파일을 복사했다"는 **성공** 의미입니다.
- `.git`을 빼는 이유: 복사본에서 실수로 커밋하거나 원격 저장소로 push하는 일을 막기 위해서입니다. 대신 복사본에서는 "마지막 수정" 시각이 표시되지 않는데, 그 이유는 4-3에서 봅니다.
- `node_modules`를 빼고 복사한 뒤 `npm install`로 새로 받는 이유는 4-2에서 설명합니다.
- bash 명령은 작성에 쓴 PC(Windows)에서는 실행해 보지 못했습니다. 동작이 다르면 파일 탐색기·Finder로 복사한 뒤 `node_modules`, `.git` 폴더만 지워도 같습니다.

**확인 방법:** `ts-wiki-lab` 폴더에 `package.json`과 `docs` 폴더가 있고, `npm install` 뒤 `node_modules` 폴더가 생기면 준비 완료입니다.

::: warning 빌드는 몇 분 걸립니다
ts-wiki는 레슨이 75개라 `npx vitepress build docs` 한 번에 작성 시점 PC에서 2~3분(실측 약 133~176초)이 걸렸습니다. 옵션을 바꿀 때마다 전체를 빌드하기 부담스러우면, 4-6에서 만드는 작은 실습 프로젝트(페이지 1~2개)에서 먼저 시험해 보세요. 10초 안팎이면 끝납니다.
:::

## 막힐 때 팁

- **파일을 옆에 열어 두고 읽으세요.** 이 파트의 인용은 실제 파일과 똑같고 줄 번호도 같습니다. VS Code에서 `Ctrl+G`를 누르면 줄 번호로 바로 이동할 수 있습니다.
- **모르는 옵션은 "복사본에서 바꾸고 빌드해 보기"가 가장 빠릅니다.** 그 줄을 지우거나 값을 바꾼 뒤 빌드해, 결과 HTML에서 무엇이 달라졌는지 검색합니다.
- **에러 메시지의 파일 이름과 줄·칸 번호부터 봅니다.** VitePress 에러는 대부분 `file:`이나 `(5:13)`처럼 위치를 알려 줍니다.
- 용어가 낯설면 [Part 3. 라이브러리 사전](../part3-libraries/)으로 돌아갑니다. 특히 [VitePress: 설정 · 라우팅 · 테마](../part3-libraries/01-vitepress)와 [Vite와 Vue](../part3-libraries/02-vite-vue)를 자주 참고하게 됩니다.
