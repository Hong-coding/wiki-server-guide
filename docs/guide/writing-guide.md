# 문서 작성 규칙

이 가이드의 모든 레슨은 같은 뼈대를 따릅니다. 새 문서를 쓰거나 고칠 때 이 규칙을 지켜 주세요.

## 독자

- **서버를 한 번도 띄워 본 적 없는 사람**이 기준입니다. 터미널을 여는 법부터 모를 수 있습니다.
- 처음 나오는 용어는 그 자리에서 풀어 씁니다. 예: "포트(port, 한 컴퓨터 안에서 프로그램을 구분하는 번호)"
- "당연히", "간단히", "쉽게" 같은 말은 쓰지 않습니다.
- 설명의 기준 예제는 **ts-wiki**(`D:\workspace\ts-wiki`)입니다. 파일을 인용할 때는 실제 파일과 똑같이 씁니다.

## 레슨 뼈대

```md
---
title: 레슨 제목
---

# 레슨 제목

<LessonMeta level="입문" :minutes="40" prev="이전 레슨에서 배운 것 한 줄" />

## 이번에 배울 것
- 학습 목표 3~5개 ("~할 수 있다" 형태)

## 먼저 알아 둘 것
- 선수 지식과 링크 (없으면 "없음")

## 비유로 이해하기
- 일상의 비유로 핵심을 먼저 잡습니다.

## 개념 설명 (실습 레슨이면 "따라 하기")
- 작은 단계로 나눕니다(###).
- 명령 → 실제 출력 → 해설 → **확인 방법**(무엇이 보이면 성공인가) 순서를 지킵니다.

## ts-wiki에서는
- 이 개념이 ts-wiki의 어느 파일·어느 줄에 어떻게 쓰였는지 연결합니다.

## 자주 하는 실수
- "증상(에러 메시지) → 원인 → 해결" 3개 이상

## 직접 해 보기
- 실습 과제 3~5개. 난이도 ⭐ 기초 / ⭐⭐ 응용 / ⭐⭐⭐ 도전
- 각 과제 아래에 정답·힌트를 접어 둡니다.

## 확인 퀴즈
- 3~5문항 (정답 접어 두기)

## 정리
- 핵심 요약 3~7줄

## 다음 단계
- 다음 레슨 링크와 한 줄 소개
```

## 마크다운 작성 시 주의 (VitePress 빌드 오류 방지)

1. 본문에서 꺾쇠(`<`, `>`)가 들어간 표현은 반드시 인라인 코드로 감쌉니다. 맨글자로 쓰면 HTML 태그로 해석됩니다.
2. 이중 중괄호는 **코드 블록(```) 안에만** 씁니다. 인라인 코드(백틱 한 쌍) 안에 써도 Vue가 템플릿 문법으로 해석해 빌드가 깨집니다. GitHub Actions의 `github.event.repository.name` 같은 표현식을 본문에서 말할 때는 중괄호 없이 이름만 쓰거나, 꼭 필요하면 `<span v-pre>` 안에 넣습니다.
3. 코드 블록은 언어를 지정합니다: `bash`, `powershell`, `ts`, `js`, `json`, `yaml`, `nginx`, `dockerfile`, `vue`, `text`.
4. 정답·해설은 `::: details 정답 보기` 접기 블록을 씁니다.
5. 강조 박스는 `::: tip`, `::: warning`, `::: danger`, `::: info`를 씁니다.
6. frontmatter `title`에 콜론(`:`)이 들어가면 작은따옴표로 감쌉니다(`npm run fix:frontmatter`가 자동으로 고칩니다).
7. 내부 링크는 상대 경로, 확장자 `.md` 생략. 없는 페이지로 링크하면 빌드가 실패합니다.
8. 표 셀 안의 `|`는 `\|`로 씁니다.

## 명령과 출력 규칙

- 명령은 **실제로 실행해 본 것만** 씁니다. 출력은 실제 출력을 옮기되, 길면 `...`로 줄입니다.
- Windows(PowerShell)와 macOS/Linux(bash)에서 명령이 다르면 둘 다 적습니다.
- 버전에 따라 달라지는 내용은 버전을 밝힙니다. 예: "작성 시점(2026-10) 기준 VitePress 1.6.3"
- 실제 PC의 IP·사용자 이름·토큰 같은 값은 쓰지 않고 `<이 PC의 IP>`, `<사용자>`처럼 자리 표시로 씁니다.
