# Part 0. 시작하기

이 파트는 **서버를 한 번도 띄워 본 적 없는 분**을 위한 출발점입니다. 터미널(검은 창에 명령을 입력하는 프로그램)을 열어 본 적이 없어도 괜찮습니다. 이 파트를 마치면 이 가이드가 무엇을 만들려고 하는지 큰 그림을 그릴 수 있고, 실습에 필요한 도구가 내 PC에 모두 설치되어 있게 됩니다.

<PartLessons dir="part0-start" />

## 이 파트가 왜 필요한가요?

서버 공부를 시작한 사람이 가장 먼저 막히는 곳은 의외로 "서버"가 아닙니다.

- **지금 무엇을 하고 있는지 모릅니다.** `npm run dev`, `docker compose up`, `git push`가 각각 전체 그림의 어디에 해당하는지 모르면, 명령은 외웠는데 문제가 생겼을 때 손을 쓸 수 없습니다.
- **공부하는 방법을 모릅니다.** 서버는 책으로만 읽어서는 익혀지지 않습니다. 켜 보고, 꺼 보고, 일부러 망가뜨려 봐야 감이 옵니다. 그런데 무엇을 어떻게 망가뜨려야 안전한지 모르면 시작을 못 합니다.
- **도구가 제대로 설치되어 있지 않습니다.** `'npm'은(는) 내부 또는 외부 명령...이 아닙니다` 같은 문장을 처음 보면 무엇이 잘못됐는지 짐작조차 어렵습니다.

그래서 Part 0은 **큰 그림 → 공부하는 법 → 도구 설치** 순서로 기초 체력을 먼저 만듭니다.

## 학습 흐름

| 순서 | 레슨 | 무엇을 하나요 |
|---|---|---|
| 1 | 이 가이드에서 만들 것 | ts-wiki가 마크다운에서 시작해 브라우저 화면이 되기까지의 전체 그림을 봅니다. |
| 2 | 서버 구축을 공부하는 법 | 터미널 여는 법, 로그 읽는 습관, 실습용 복사본에서 작업하기, 질문하는 법을 익힙니다. |
| 3 | 준비물 설치 | Node.js · Git · VS Code · Docker Desktop을 설치하고, 명령으로 설치를 확인합니다. |

::: tip 설치부터 해 두고 싶다면
1·2번 레슨은 읽기 중심이고, 3번 레슨은 설치 중심입니다. 설치 프로그램을 받는 데 시간이 걸리니, 3번 레슨의 설치 파일을 먼저 받아 두고 기다리는 동안 1·2번을 읽어도 됩니다.
:::

## 이 파트를 마치면

- ts-wiki가 "마크다운 → VitePress 빌드 → HTML → 서버 → 브라우저" 순서로 화면에 나타난다는 것을 그림으로 설명할 수 있습니다.
- 이 가이드의 각 파트가 그 그림의 어느 부분을 다루는지 압니다.
- 터미널을 열고, 서버를 켜고 끄고, 로그에서 중요한 줄을 찾는 습관이 생깁니다.
- 내 PC에 `node`, `npm`, `git`, `code`, `docker` 명령이 설치되어 있고 버전을 확인할 수 있습니다.

## 막힐 때

- **용어가 낯설다** → 지금 다 이해하지 않아도 됩니다. 1번 레슨의 그림만 기억하면 Part 1에서 하나씩 풀어 설명합니다. 급하면 [용어 사전](../appendix/02-glossary)을 찾아봅니다.
- **설치가 안 된다** → 3번 레슨의 "자주 하는 실수"를 먼저 봅니다. 대부분은 "터미널을 새로 열지 않았다" 또는 "Docker Desktop이 켜져 있지 않다"입니다.
- **일단 화면부터 보고 싶다** → 설치를 마친 뒤 [5분 만에 바로 띄우기](../guide/quickstart)를 해 보고 돌아와도 됩니다.
- **질문하고 싶다** → 2번 레슨의 "막힐 때 질문하는 법"대로 명령·출력·환경을 함께 적어 질문합니다.
