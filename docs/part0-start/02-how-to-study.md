# 서버 구축을 공부하는 법

<LessonMeta level="입문" :minutes="20" prev="ts-wiki는 원고(마크다운) → 빌드 → HTML → 서버 → 브라우저 순서로 화면에 뜬다" />

## 이번에 배울 것

- 서버 공부가 다른 공부와 어떻게 다른지(켜고, 끄고, 망가뜨려 보기) 설명할 수 있다.
- Windows와 macOS에서 터미널을 열고, 서버를 켠 터미널을 `Ctrl+C`로 끌 수 있다.
- 터미널에 찍힌 로그(log)에서 "어디서, 무엇이, 왜" 잘못됐는지 찾는 순서를 안다.
- 원본을 망가뜨리지 않도록 실습용 복사본을 만들 수 있다.
- 막혔을 때 다른 사람이 바로 도와줄 수 있게 질문을 쓸 수 있다.

## 먼저 알아 둘 것

- [이 가이드에서 만들 것](./01-what-we-build)의 전체 그림
- 이 레슨의 명령은 Node.js와 Git이 설치되어 있어야 따라 할 수 있습니다. 아직이라면 읽기만 하고, [준비물 설치](./03-setup)를 마친 뒤 다시 와서 실행해 봅니다.

## 비유로 이해하기

서버 공부는 **자전거 배우기**와 비슷합니다.

- 자전거 타는 법을 책으로 백 번 읽어도 실제로 타 보지 않으면 못 탑니다. 서버도 설명을 읽는 것보다 **직접 켜 보는 것**이 먼저입니다.
- 자전거는 넘어져 봐야 균형을 잡습니다. 서버도 **일부러 망가뜨려 봐야** 망가졌을 때 무엇이 보이는지 압니다. 포트를 겹치게 띄워 보고, 설정 파일에 오타를 내 보고, 어떤 에러가 나는지 봅니다.
- 다만 넘어지는 연습은 차가 다니는 큰길이 아니라 **빈 운동장**에서 합니다. 서버도 원본 프로젝트가 아니라 **실습용 복사본**에서 망가뜨립니다.
- 넘어졌을 때 "어디가 아프냐"는 질문에 "그냥 아파요"라고 답하면 도와줄 수가 없습니다. 서버도 막혔을 때 **무엇을 했고, 무엇이 보였는지** 정확히 말해야 도움을 받습니다.

## 개념 설명

### 서버 공부의 특징: 켜고, 끄고, 망가뜨려 보기

프로그래밍 문법 공부는 코드를 쓰고 결과를 보면 끝납니다. 서버 공부에는 단계가 하나 더 있습니다. **서버는 켜 둔 동안 계속 살아 있는 프로그램**이기 때문입니다.

| 단계 | 하는 일 | 배우는 것 |
|---|---|---|
| 켜기 | `npm run dev`, `docker compose up` | 서버가 어떤 주소·포트에서 기다리는지 |
| 접속하기 | 브라우저나 `curl`로 요청 보내기 | 요청과 응답이 실제로 오가는 모습 |
| 끄기 | `Ctrl+C`, `docker compose down` | 서버가 사라지면 무엇이 보이는지("연결할 수 없음") |
| 망가뜨리기 | 포트 겹치기, 설정 오타, 파일 지우기 | 에러 메시지의 생김새와 원인 |
| 고치기 | 로그를 읽고 원인을 하나씩 지우기 | 문제 해결 순서 |

이 다섯 단계를 한 번씩 돌 때마다 실력이 오릅니다. 특히 **망가뜨리기**를 건너뛰지 마세요. 처음 보는 에러는 무섭지만, 내가 일부러 낸 에러는 원인을 이미 알고 있으니 무섭지 않습니다. 나중에 진짜 사고가 났을 때 "아, 이건 그때 본 그 메시지다" 하고 알아볼 수 있습니다.

::: tip 서버를 켰으면 반드시 끄고 끝냅니다
켜 둔 서버를 잊으면 다음 실습에서 "포트가 이미 사용 중"이라는 에러를 만납니다. 실습이 끝나면 터미널에서 `Ctrl+C`, Docker라면 `docker compose down`을 습관처럼 실행합니다.
:::

### 터미널 여는 법

**터미널**(terminal)은 마우스 대신 글자로 컴퓨터에 명령을 내리는 창입니다. 터미널 안에서 명령을 해석해 실행하는 프로그램을 **셸**(shell)이라고 하는데, Windows에서는 주로 PowerShell, macOS·Linux에서는 주로 zsh·bash를 씁니다.

**Windows**

1. 시작 버튼을 누르고 `터미널` 또는 `PowerShell`을 입력해 엽니다. Windows 11에는 "터미널"(Windows Terminal) 앱이 기본으로 들어 있고, 열면 PowerShell이 실행됩니다.
2. 탐색기에서 폴더를 연 뒤 빈 곳을 마우스 오른쪽 클릭 → **터미널에서 열기**를 누르면, 그 폴더 위치에서 바로 시작합니다.

**macOS**

1. `Cmd+Space`로 Spotlight를 열고 `터미널`(Terminal)을 입력해 엽니다.
2. Finder에서 폴더를 마우스 오른쪽 클릭 → 서비스 → **폴더에서 새로운 터미널**로 열 수도 있습니다.

**VS Code 안에서 (양쪽 공통, 가장 추천)**

VS Code에서 프로젝트 폴더를 연 뒤 `` Ctrl+` ``(백틱, 키보드 숫자 1 왼쪽 키)를 누르면 아래쪽에 터미널이 열립니다. 이미 프로젝트 폴더 위치에서 시작하므로 `cd`로 이동할 필요가 없습니다. 오른쪽 위 `+` 버튼으로 터미널을 여러 개 띄울 수 있어서, **하나는 서버용, 하나는 명령용**으로 나눠 쓰기 좋습니다.

### 터미널 기본 명령 다섯 개

이 가이드를 따라오는 데 필요한 명령은 많지 않습니다. 아래 다섯 개면 충분합니다.

| 하고 싶은 일 | Windows (PowerShell) | macOS/Linux (bash·zsh) |
|---|---|---|
| 지금 위치 보기 | `pwd` 또는 `Get-Location` | `pwd` |
| 폴더 안 목록 보기 | `ls` 또는 `dir` | `ls` |
| 폴더 이동 | `cd D:\workspace\ts-wiki` | `cd ~/workspace/ts-wiki` |
| 한 단계 위로 | `cd ..` | `cd ..` |
| 실행 중인 명령 멈추기 | `Ctrl+C` | `Ctrl+C` |

PowerShell에서는 경로에 `/`를 써도 대부분 동작합니다. 이 가이드는 Windows 예시에서 `D:/workspace/ts-wiki`처럼 `/`를 쓰기도 하는데, `\`로 바꿔 써도 같습니다.

::: warning Ctrl+C는 "복사"가 아닙니다
터미널에서 서버가 실행 중일 때 `Ctrl+C`를 누르면 **서버가 꺼집니다.** 터미널 글자를 복사하고 싶다면 마우스로 드래그한 뒤 Windows Terminal에서는 `Ctrl+Shift+C`(또는 마우스 오른쪽 클릭), macOS에서는 `Cmd+C`를 씁니다.
:::

### 로그 읽는 습관

**로그**(log)는 프로그램이 "지금 무엇을 하고 있는지" 터미널이나 파일에 남기는 기록입니다. 서버 문제의 답은 거의 언제나 로그에 이미 적혀 있습니다. 문제는 사람이 그것을 읽지 않는다는 것입니다.

#### 정상 로그부터 눈에 익힌다

먼저 **잘 될 때의 모습**을 알아야 이상할 때를 알아챕니다. 다음은 ts-wiki 복사본에서 개발 서버를 켰을 때 실제로 찍힌 로그입니다(포트만 실습용으로 바꿨습니다).

```text
  vitepress v1.6.3

  ➜  Local:   http://localhost:5198/
  ➜  Network: http://<이 PC의 IP>:5198/
```

여기서 읽어야 할 것은 세 가지입니다.

- `vitepress v1.6.3` → 어떤 프로그램, 어떤 버전이 떴는가
- `Local: http://localhost:5198/` → 내 PC에서 접속할 주소
- `Network: ...` → 같은 네트워크의 다른 PC에서 접속할 주소

그리고 **로그가 여기서 멈춰 있는 것이 정상**입니다. 서버는 요청을 기다리는 중이라 다음 명령을 입력받는 줄(프롬프트)이 돌아오지 않습니다. "멈췄다, 고장 났다"가 아니라 "켜져서 기다리는 중"입니다.

#### 에러 로그는 위에서 아래로, 핵심 한 줄을 찾는다

같은 포트로 서버를 하나 더 켜려고 하면 어떻게 될까요? 이번 레슨용으로 만든 작은 Node.js 서버를 두 번 실행했을 때 실제로 나온 로그입니다.

```text
node:events:486
      throw er; // Unhandled 'error' event
      ^

Error: listen EADDRINUSE: address already in use 0.0.0.0:5196
    at Server.setupListenHandle [as _listen2] (node:net:1940:16)
    at listenInCluster (node:net:1997:12)
    ...
  code: 'EADDRINUSE',
  errno: -4091,
  syscall: 'listen',
  address: '0.0.0.0',
  port: 5196
}

Node.js v24.13.1
```

글자는 많지만 읽는 순서는 정해져 있습니다.

1. **`Error:`로 시작하는 줄을 찾습니다.** → `Error: listen EADDRINUSE: address already in use 0.0.0.0:5196`
2. **대문자 코드를 찾습니다.** → `EADDRINUSE`. "주소(포트)가 이미 사용 중"이라는 뜻의 고정된 이름이라 검색하기 좋습니다.
3. **숫자·경로·주소 같은 구체적인 값을 찾습니다.** → `5196`. 몇 번 포트가 문제인지 알 수 있습니다.
4. `at ...`으로 시작하는 줄(스택 트레이스, 오류가 난 코드 위치 목록)은 **처음에는 건너뜁니다.** 내 코드가 아니라 Node.js 내부 위치라서 초보 단계에서는 단서가 거의 없습니다.

VitePress는 같은 상황에서 친절하게 다음 포트로 넘어갑니다. 이것도 실제 로그입니다.

```text
Port 5198 is in use, trying another one...

  vitepress v1.6.3

  ➜  Local:   http://localhost:5199/
```

이 경우 에러는 나지 않지만, **주소가 5198이 아니라 5199로 바뀌었다**는 것을 로그에서 읽지 못하면 엉뚱한 주소로 접속하게 됩니다. 로그를 "에러가 났을 때만" 읽지 말고, 서버를 켤 때마다 한 번씩 읽는 습관을 들입니다.

#### npm 에러는 "npm error" 줄을 본다

`npm run`으로 없는 스크립트를 실행했을 때의 실제 출력입니다.

```text
npm error Missing script: "hello"
npm error
npm error To see a list of scripts, run:
npm error   npm run
npm error A complete log of this run can be found in: C:\Users\<사용자>\AppData\Local\npm-cache\_logs\2026-10-28T00_12_28_139Z-debug-0.log
```

첫 줄 `Missing script: "hello"`가 원인이고, 둘째 덩어리 `To see a list of scripts, run: npm run`이 해결 방법입니다. 에러 메시지가 해결 방법까지 알려 주는 경우가 생각보다 많습니다.

::: tip 로그 읽기 3단계 요약
① `Error`·`error`·`ERR`가 들어간 첫 줄 → ② 대문자 코드(`EADDRINUSE`, `ENOENT` 등)나 숫자 → ③ 메시지가 제안하는 해결 방법. 스택 트레이스(`at ...`)는 맨 나중에.
:::

### 실습용 복사본에서 작업하기

이 가이드에는 "일부러 망가뜨려 보세요"라는 과제가 자주 나옵니다. 그때마다 원본 `D:\workspace\ts-wiki`를 고치면, 망가진 채로 되돌리지 못할 수 있습니다. 그래서 **실습용 복사본**을 따로 만들어 씁니다.

가장 깔끔한 방법은 `git clone`입니다. Git으로 관리되는 폴더는 다른 폴더로 그대로 복제할 수 있고, Git이 무시하도록 설정된 `node_modules`나 `dist` 같은 큰 폴더는 따라오지 않습니다.

```powershell
# Windows (PowerShell): 실습 폴더로 이동해 복제
cd D:\practice
git clone D:/workspace/ts-wiki ts-wiki-practice
```

```bash
# macOS/Linux
cd ~/practice
git clone ~/workspace/ts-wiki ts-wiki-practice
```

실제 출력:

```text
Cloning into 'ts-wiki-practice'...
done.
```

그런데 이렇게 만든 복사본은 **원본을 "origin"(원래 저장소)으로 기억**합니다.

```bash
cd ts-wiki-practice
git remote -v
```

```text
origin	D:/workspace/ts-wiki (fetch)
origin	D:/workspace/ts-wiki (push)
```

이 상태에서 실수로 `git push`를 하면 원본에 변경이 들어갈 수 있습니다. 실습용이라면 연결을 끊어 둡니다.

```bash
git remote remove origin
git remote -v
```

두 번째 명령이 **아무것도 출력하지 않으면** 성공입니다. 이제 이 폴더에서는 무엇을 해도 원본에 영향이 없습니다.

**확인 방법**: 복사본 폴더에 `package.json`, `docs`, `Dockerfile` 등이 보이고, `git remote -v`가 빈 출력이면 성공입니다. 복사본에서 실습하려면 `npm install`을 한 번 실행해 `node_modules`를 새로 받아야 합니다([Node.js와 npm](../part1-concepts/04-node-npm)에서 설명).

::: info Git 저장소가 아닌 폴더라면
탐색기에서 폴더를 통째로 복사해도 됩니다. 다만 `node_modules`(수만 개의 작은 파일)까지 복사하면 오래 걸리니, 복사 전에 `node_modules` 폴더는 빼고 복사한 뒤 복사본에서 `npm install`을 실행합니다.
:::

### 하나씩만 바꾸고, 바꾼 것을 적어 둔다

망가뜨리기 실습에서 가장 중요한 규칙은 **한 번에 하나만 바꾸는 것**입니다. 포트도 바꾸고 설정도 바꾸고 파일도 지운 뒤 에러가 나면, 무엇 때문인지 알 수 없습니다.

```text
[실습 노트 예시] 2026-10-28
- 바꾼 것: 개발 서버를 터미널 두 개에서 같은 포트로 실행
- 결과: 두 번째 터미널에 "Port 5198 is in use, trying another one..." → 5199로 뜸
- 되돌림: 두 번째 터미널 Ctrl+C
- 배운 것: VitePress는 포트가 겹치면 에러 대신 다음 번호로 넘어간다. 주소를 꼭 로그에서 확인할 것
```

메모장이나 마크다운 파일에 이렇게 적어 두면, 몇 주 뒤 같은 에러를 만났을 때 검색 대신 내 노트를 찾으면 됩니다.

### 막힐 때 질문하는 법

혼자 30분 이상 막혔다면 질문할 때입니다. 좋은 질문에는 다음 다섯 가지가 들어 있습니다.

1. **하려던 것**: "ts-wiki 복사본을 Docker로 띄우려고 했습니다."
2. **실행한 명령**: 터미널에 입력한 그대로 복사합니다. `docker compose up -d --build`
3. **실제 출력**: 에러 메시지를 **글자로** 복사합니다(스크린숏보다 글자가 검색·복사하기 좋습니다). 앞뒤 몇 줄도 함께.
4. **환경**: OS, 버전. `node -v`, `npm -v`, `docker --version`의 출력.
5. **이미 해 본 것**: "Docker Desktop을 재시작해 봤지만 같았습니다."

```text
[질문 예시]
하려던 것: ts-wiki 복사본을 개발 서버로 띄우기
명령: npm run dev
출력:
  npm error code ENOENT
  npm error syscall open
  npm error path C:\Users\<사용자>\package.json
  ...
환경: Windows 11, node v24.13.1, npm 11.8.0
해 본 것: npm install 다시 실행 → 같은 에러
```

이 질문을 받은 사람은 출력의 `path` 줄을 보고 "홈 폴더에서 실행하셨네요. `package.json`이 있는 프로젝트 폴더로 `cd`한 뒤 다시 해 보세요"라고 바로 답할 수 있습니다. 이 다섯 가지를 적다 보면 **질문을 보내기 전에 스스로 답을 찾는 경우**도 많습니다.

::: danger 질문에 넣으면 안 되는 것
비밀번호, 토큰, API 키, 회사 내부 서버의 실제 IP·주소, 고객 정보는 지우거나 `<이 PC의 IP>`, `<토큰>`처럼 바꿔 적습니다. 로그를 통째로 붙여 넣을 때 특히 조심합니다. 위 예시의 npm 로그 경로에도 사용자 이름이 들어 있어 `<사용자>`로 바꿨습니다.
:::

AI 도구에 질문할 때도 똑같은 다섯 가지를 넣으면 훨씬 정확한 답이 옵니다. 다만 답으로 받은 명령은 **무엇을 하는 명령인지 이해한 뒤** 실습용 복사본에서 먼저 실행합니다.

## ts-wiki에서는

ts-wiki 자체에도 "켜고 끄기", "망가뜨려 보며 확인하기" 습관이 설계에 들어 있습니다.

- **켜고 끄는 명령이 `package.json`에 이름 붙어 정리되어 있습니다.** 긴 명령을 외울 필요 없이 `npm run dev`, `npm run build`, `npm run preview`만 기억하면 됩니다.

```json
  "scripts": {
    "dev": "vitepress dev docs --host 0.0.0.0 --port 5180",
    "build": "vitepress build docs",
    "fix:frontmatter": "node scripts/fix-frontmatter.mjs",
    "preview": "vitepress preview docs --host 0.0.0.0 --port 5180"
  },
```

- **빌드가 일부러 실패하도록 되어 있는 부분이 있습니다.** `README.md`에는 이렇게 적혀 있습니다.

```text
결과물은 `docs/.vitepress/dist`에 생깁니다. 존재하지 않는 페이지로 링크하면 빌드가 실패하므로, 문서를 고친 뒤에는 꼭 빌드해 봅니다.
```

VitePress는 없는 페이지로 가는 링크(죽은 링크)를 발견하면 빌드를 멈춥니다. 귀찮아 보이지만, 사이트에 깨진 링크가 올라가기 전에 **내 PC에서 먼저 망가진 것을 알려 주는 장치**입니다. 실습용 복사본에서 레슨 하나에 `[없는 링크](./nothing)`을 넣고 `npm run build`를 해 보면, 그 로그를 직접 볼 수 있습니다.

- **원본을 지키는 구조입니다.** `.gitignore`에 `node_modules/`, `docs/.vitepress/dist/`가 들어 있어서, `git clone`으로 만든 복사본에는 이 폴더들이 따라오지 않습니다. 위에서 복사본을 `git clone`으로 만든 이유입니다.

## 자주 하는 실수

### 1. 서버가 "멈췄다"며 터미널을 닫아 버린다

- **증상**: `npm run dev` 후 로그가 더 이상 올라오지 않고 프롬프트도 안 돌아와서, 고장인 줄 알고 창을 닫습니다. 그러면 브라우저에서 `localhost:5180`이 열리지 않습니다.
- **원인**: 서버는 요청을 기다리는 동안 그 터미널을 계속 차지합니다. 프롬프트가 안 돌아오는 것이 **정상**입니다. 창을 닫으면 서버도 함께 꺼집니다.
- **해결**: 서버용 터미널은 그대로 두고, 다른 명령은 새 터미널(VS Code의 `+` 버튼)에서 실행합니다.

### 2. 다른 폴더에서 명령을 실행한다

- **증상**: `npm error Missing script: "dev"` 또는 `npm error code ENOENT ... package.json`
- **원인**: `package.json`이 없는 폴더(예: 사용자 홈 폴더)에서 `npm run dev`를 실행했습니다.
- **해결**: `pwd`로 지금 위치를 확인하고, `cd`로 프로젝트 폴더(=`package.json`이 있는 폴더)로 이동한 뒤 다시 실행합니다. `ls`를 쳤을 때 `package.json`이 보여야 합니다.

### 3. 에러 메시지를 읽지 않고 같은 명령만 반복한다

- **증상**: 같은 명령을 다섯 번 실행했는데 계속 실패합니다.
- **원인**: 원인이 그대로인데 결과가 달라질 리 없습니다. 대부분 메시지 첫 줄에 원인이 적혀 있습니다.
- **해결**: "로그 읽기 3단계"대로 `Error` 줄 → 대문자 코드 → 제안된 해결 방법 순서로 읽고, 그 코드로 검색합니다.

### 4. 원본 프로젝트에서 망가뜨리기 실습을 한다

- **증상**: 실습 후 원래 잘 되던 ts-wiki가 안 뜨는데, 무엇을 바꿨는지 기억나지 않습니다.
- **원인**: 원본에서 여러 군데를 고쳤습니다.
- **해결**: 원본이 Git으로 관리된다면 `git status`로 바뀐 파일을 확인하고, `git diff`로 내용을 봅니다. 앞으로는 `git clone`으로 만든 복사본에서 실습합니다.

## 직접 해 보기

### 과제 1 ⭐ 터미널 세 가지 방법으로 열기

시작 메뉴(또는 Spotlight), 탐색기(또는 Finder)의 "터미널에서 열기", VS Code의 `` Ctrl+` `` 세 가지 방법으로 터미널을 열고, 각각 `pwd`를 실행해 시작 위치가 어떻게 다른지 비교합니다.

::: details 정답 보기
- 시작 메뉴로 연 터미널: 사용자 홈 폴더(`C:\Users\<사용자>` 또는 `/Users/<사용자>`)에서 시작합니다.
- 탐색기·Finder에서 연 터미널: 그 폴더에서 시작합니다.
- VS Code 터미널: VS Code로 연 프로젝트 폴더에서 시작합니다.

그래서 프로젝트 작업은 VS Code 터미널이 가장 편합니다.
:::

### 과제 2 ⭐ 실습용 복사본 만들기

ts-wiki를 `git clone`으로 복제하고, `git remote remove origin`으로 원본과의 연결을 끊습니다.

::: details 확인 방법
복사본 폴더에서 `git remote -v`가 아무것도 출력하지 않고, `ls`에 `package.json`·`docs`가 보이면 성공입니다.
:::

### 과제 3 ⭐⭐ 로그에서 핵심 찾기

다음 로그에서 "원인", "문제의 값", "해결 힌트"를 각각 한 줄씩 골라 봅니다.

```text
npm error code ENOENT
npm error syscall open
npm error path C:\Users\<사용자>\package.json
npm error errno -4058
npm error enoent Could not read package.json: Error: ENOENT: no such file or directory, open 'C:\Users\<사용자>\package.json'
npm error enoent This is related to npm not being able to find a file.
```

::: details 정답 보기
- 원인: `ENOENT: no such file or directory` (파일이 없음)
- 문제의 값: `C:\Users\<사용자>\package.json` → 홈 폴더에서 명령을 실행했다는 뜻
- 해결 힌트: `package.json`이 있는 프로젝트 폴더로 `cd`한 뒤 다시 실행합니다.
:::

### 과제 4 ⭐⭐⭐ 일부러 망가뜨리고 질문 쓰기

실습용 복사본에서 개발 서버를 두 개의 터미널에서 동시에 `npm run dev`로 켜 봅니다. 두 번째 터미널의 로그를 읽고, 이 레슨의 "질문 다섯 가지" 형식으로 질문을 써 봅니다. 그다음 질문에 스스로 답해 봅니다. 끝나면 두 터미널 모두 `Ctrl+C`로 끕니다.

::: details 힌트와 정답
두 번째 터미널에는 `Port 5180 is in use, trying another one...`이 찍히고 `5181` 같은 다음 번호로 뜹니다. 질문을 쓰다 보면 "이미 첫 번째 터미널에서 5180을 쓰고 있다"는 답이 로그 첫 줄에 있다는 것을 알게 됩니다. 실습이 끝나면 두 서버를 모두 끄는 것까지가 과제입니다.
:::

## 확인 퀴즈

1. `npm run dev`를 실행했더니 프롬프트가 돌아오지 않습니다. 고장인가요?
2. 서버가 실행 중인 터미널에서 `Ctrl+C`를 누르면 어떻게 되나요?
3. 에러 로그에서 가장 먼저 찾아야 할 줄은 무엇인가요?
4. `git clone`으로 만든 실습용 복사본에서 `git remote remove origin`을 하는 이유는 무엇인가요?
5. 질문할 때 꼭 넣어야 할 다섯 가지는 무엇인가요?

::: details 정답 보기
1. 아닙니다. 서버가 요청을 기다리는 중인 정상 상태입니다.
2. 서버가 꺼집니다. 복사가 아닙니다.
3. `Error`(또는 `error`, `ERR`)로 시작하는 줄과 그 안의 대문자 코드입니다.
4. 실수로 `git push`해도 원본 저장소에 변경이 들어가지 않게 하려고입니다.
5. 하려던 것, 실행한 명령, 실제 출력, 환경(OS·버전), 이미 해 본 것입니다.
:::

## 정리

- 서버 공부는 **켜기 → 접속하기 → 끄기 → 망가뜨리기 → 고치기**를 반복하는 것입니다.
- 터미널은 VS Code의 `` Ctrl+` ``로 여는 것이 가장 편하고, 서버용·명령용 터미널을 나눠 씁니다.
- 서버를 켜면 프롬프트가 돌아오지 않는 것이 정상이고, `Ctrl+C`로 끕니다.
- 로그는 `Error` 줄 → 대문자 코드·숫자 → 제안된 해결 방법 순서로 읽습니다. 정상 로그도 매번 읽습니다.
- 망가뜨리기 실습은 `git clone` 후 `git remote remove origin`으로 만든 복사본에서, 한 번에 하나씩 합니다.
- 질문에는 하려던 것·명령·출력·환경·해 본 것을 넣고, 비밀 값은 지웁니다.
