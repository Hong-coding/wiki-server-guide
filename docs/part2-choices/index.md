# Part 2. 기술 선택의 이유

<PartLessons dir="part2-choices" />

## 이 파트가 왜 필요한가

Part 1에서 "브라우저가 서버에 파일을 달라고 하고, 서버가 HTML을 돌려준다"는 큰 그림을 잡았습니다. 실제로 위키를 만들려고 하면 고를 것이 한꺼번에 생깁니다.

- 위키 프로그램은 무엇을 쓸까? (VitePress? Docusaurus? Wiki.js? Notion?)
- 글은 어떤 형식으로 쓸까? (Markdown? HTML? 웹 편집기?)
- 설정 파일과 화면 부품은 어떤 언어로 쓸까? (JavaScript? TypeScript?)
- 다 만든 위키는 어디에 띄울까? (GitHub Pages? 사내 서버? 클라우드?)

처음 서버를 만드는 사람은 보통 "검색해서 제일 먼저 나온 것"이나 "남들이 많이 쓴다는 것"을 고릅니다. 그래도 일단은 돌아갑니다. 문제는 몇 달 뒤에 생깁니다. 글이 300개가 되었는데 다른 도구로 옮길 수 없거나, 무료 요금제가 바뀌어 비용이 생기거나, 사내망에서는 쓸 수 없는 서비스였다는 것을 그제야 알게 됩니다.

이 파트는 ts-wiki를 만든 사람이 **무엇이 필요했고, 어떤 후보를 놓고, 무엇을 포기하고 무엇을 골랐는지**를 그대로 보여 줍니다. 정답을 외우는 파트가 아니라 **고르는 방법**을 배우는 파트입니다. 여러분의 상황이 ts-wiki와 다르면 다른 답이 나와야 정상입니다.

## ts-wiki의 요구사항 (이 파트 전체의 기준)

모든 레슨이 아래 일곱 가지 요구사항을 기준으로 후보를 비교합니다. 먼저 한 번 읽어 두세요.

| # | 요구사항 | 왜 필요했나 |
|---|---|---|
| 1 | 초보자용 학습 위키 | 프로그래밍을 처음 배우는 사람이 순서대로 따라 읽어야 합니다. 사이드바와 이전/다음 레슨 버튼이 중요합니다. |
| 2 | 코드 예제가 많음 | TypeScript 위키라서 페이지마다 코드 블록이 여러 개입니다. 색 입히기(하이라이트)와 줄 번호가 필요합니다. |
| 3 | 무료로 인터넷에 공개 | 누구나 볼 수 있어야 하고, 운영비가 들면 안 됩니다. |
| 4 | 사내 서버에도 띄울 수 있어야 함 | 인터넷이 막힌 사내망에서도 같은 위키를 봐야 합니다. |
| 5 | 한 사람이 관리 | 서버 관리자가 따로 없습니다. 고장 날 부품이 적어야 합니다. |
| 6 | 검색 | 레슨이 75개라서 검색이 없으면 원하는 내용을 찾기 어렵습니다. |
| 7 | 다크 모드 | 오래 읽는 문서라 어두운 화면을 원하는 사람이 많습니다. |

## 학습 흐름

```text
2-1 위키 도구 비교        ─ 후보 6가지를 같은 기준표로 비교
   ↓
2-2 왜 VitePress인가      ─ 고른 도구의 장점과 그 대가(빌드가 깨지는 함정)
   ↓
2-3 왜 Markdown인가       ─ 글 형식: git diff · 리뷰 · 이식성
   ↓
2-4 왜 TypeScript인가     ─ 설정·컴포넌트 언어: 타입이 실수를 잡는 장면을 직접 확인
   ↓
2-5 왜 Pages + Docker인가 ─ 배포 방식: 인터넷 공개와 사내 서버를 둘 다 준비한 이유
```

각 레슨은 같은 순서로 진행합니다.

1. **요구사항** — 이 결정에서 무엇이 중요했나
2. **후보 비교표** — 장점·단점·어울리는 상황
3. **ts-wiki의 결정과 그 대가** — 무엇을 얻고 무엇을 포기했나(트레이드오프, trade-off: 하나를 얻으려고 다른 하나를 내주는 것)
4. **이럴 땐 다른 걸 고르세요** — 상황이 다르면 답이 달라지는 경우

## 이 파트를 마치면 할 수 있는 것

- 위키·문서 사이트 도구를 고를 때 무엇을 기준으로 비교해야 하는지 말할 수 있습니다.
- "ts-wiki는 왜 VitePress·Markdown·TypeScript·GitHub Pages·Docker를 썼나요?"라는 질문에 대안과 함께 답할 수 있습니다.
- 내 상황(팀 규모, 공개 여부, 사내망 여부)에 맞는 다른 조합을 스스로 고를 수 있습니다.
- 기술 선택을 "요구사항 → 후보 → 결정 → 대가" 순서로 문서에 남길 수 있습니다.

## 막힐 때 팁

::: tip 모르는 도구 이름이 나와도 괜찮습니다
이 파트에는 Docusaurus, MkDocs, Wiki.js, Netlify처럼 처음 듣는 이름이 많이 나옵니다. 전부 설치해 볼 필요는 없습니다. **비교표의 "어울리는 상황" 열만** 이해해도 충분합니다. 용어가 헷갈리면 [용어 사전](../appendix/02-glossary)을 옆에 띄워 두세요.
:::

- 이 파트는 실습보다 **읽고 판단하는** 비중이 큽니다. 대신 2-2와 2-4에는 일부러 빌드를 깨뜨려 보고, 타입 검사기로 실수를 잡아 보는 실습이 있습니다. 이 두 실습은 꼭 해 보세요.
- 가격·무료 한도·정책처럼 바뀌기 쉬운 내용은 **작성 시점(2026-10) 기준**입니다. 실제로 고를 때는 각 서비스의 공식 페이지에서 다시 확인하세요. 공식 주소는 [참고 자료](../appendix/04-resources)에 모아 두었습니다.
- "그래서 나는 뭘 써야 하나요?"가 궁금하면 각 레슨 끝의 **이럴 땐 다른 걸 고르세요** 절만 먼저 읽어도 됩니다.
- 웹 서버·정적 사이트·빌드라는 말이 아직 낯설다면 [정적 사이트와 동적 서버](../part1-concepts/02-static-vs-dynamic)와 [정적 사이트 생성기(SSG)와 빌드](../part1-concepts/05-ssg)를 먼저 복습하세요.
